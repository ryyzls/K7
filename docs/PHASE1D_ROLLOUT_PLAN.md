# Tahap 1D: rencana perubahan dan rollback

Status: DRAFT, belum dieksekusi. Engine Docker tidak dapat dihubungi pada pemeriksaan 17 November 2026. Jangan menjalankan langkah perubahan sebelum backup dapat dipulihkan dan baseline live tercatat.

1. Setelah Engine aktif, catat container ID, image ID, mount volume, network, port aktual dan health. Jangan mengekspor environment/kredensial ke laporan. Pastikan tidak ada transaksi aplikasi yang sedang berjalan sebelum maintenance.
2. Backup PostgreSQL dengan pg_dump format custom ke lokasi privat di luar Git; arsip mengandung data pasien dan harus dibatasi aksesnya. Uji pg_restore --list. Uji pemulihan backup hanya di lingkungan privat terpisah, bukan database fixture sintetis. Backup Fuseki harus konsisten: jadwalkan penghentian service terarah jika tidak tersedia backup online yang aman. Jangan menyalin TDB2 aktif sebagai backup yang dianggap valid. Simpan konfigurasi Compose dan image ID tanpa menyalin .env ke laporan.
3. Port: Compose sudah berisi loopback. Setelah backup, recreate hanya service postgres dan fuseki dengan --no-deps, tanpa down dan tanpa -v, memakai volume yang sama. Konfirmasi nama volume sebelum eksekusi. Verifikasi docker inspect PortBindings, health API, SELECT 1, COUNT RS 206, serta konektivitas service-name internal. Jika gagal, hentikan perubahan berikutnya dan pulihkan konfigurasi/image sebelumnya dengan volume yang sama; rollback port ke semua interface memerlukan keputusan keamanan eksplisit.
4. Buat database carisehat_test_phase1d dan role terbatas khusus; tidak menyalin data produksi. Guard pengujian wajib memeriksa current_database() tepat sama dengan nama test sebelum DDL/DML; gunakan koneksi test eksplisit, bukan fallback DATABASE_URL aplikasi. Beri fixture hanya data sintetis. Jangan menghapus database yang ternyata sudah ada tanpa memeriksa kepemilikannya.
5. Siapkan migrasi versioned setelah introspeksi ulang. Target: CHECK booking jenis/status, server default status, index status; selaraskan metadata ORM untuk CHECK/UNIQUE wilayah, tipe CHAR/TEXT dan default SQL. Putuskan nullable created_at berdasarkan diagnosis data, bukan alter otomatis. Tidak menambah FK booking ke tabel RS SQL tanpa menjamin sinkronisasi sumber semantik.
6. Migrasi harus transaction-safe dengan lock_timeout/statement_timeout, preflight pelanggaran dan nama constraint, serta pencatatan versi. Uji up, rerun, rollback dan kegagalan di database sintetis dengan bentuk schema live. Jangan menerapkan ke produksi sebelum semua tes lulus; jangan membersihkan data pasien untuk memaksakan constraint.
7. Uji insert/cancel, operator benar/salah/kosong, collision kode, rollback, concurrent request dan idempotency. Implementasi idempotency membutuhkan kontrak dan penyimpanan key yang jelas; tidak menganggap retry otomatis sudah idempotent. Uji kegagalan refresh setelah commit untuk risiko respons gagal walaupun data tersimpan.
8. Browser live: blok request write /api/booking, gunakan pencarian/detail/chat fallback; ukuran 375/768/1440. Simpan hanya bukti bebas data pasien; catat HTTP, console dan network failure. Tidak menonaktifkan error agar test tampak lulus.

Tidak ada backup, migrasi atau pemulihan yang diklaim selesai oleh dokumen ini.
